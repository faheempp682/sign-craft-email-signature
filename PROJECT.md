# SignCraft — Email Signature Platform (working name)

> AI-assisted email signature builder that outputs Outlook-safe HTML and installs into Gmail / Outlook / Apple Mail / Thunderbird. **Build order: internal tool first, billing and public launch last (Phase 5, after the app is complete).**

---

## 1. Vision

Start as an internal tool used only by our team. Keep the architecture clean so it can be opened to external users later if we decide to. The unique angle: **AI drafts the design, real designers (Kimp) polish it, and a compatibility engine guarantees it never breaks.**

**Positioning:** "Beautiful signatures that never break in Outlook."

---

## 2. Core Principles

1. **Deterministic rendering.** Signature HTML is generated by code from a JSON document, never free-form by AI at runtime.
2. **AI outputs JSON, not HTML.** ~10-20x fewer tokens, guaranteed safe output.
3. **Email-client reality first.** Table layouts, inline CSS, hosted PNG/GIF images, no flexbox/grid/SVG/web fonts/base64.
4. **Block-based editor, not free canvas.** Looks like a canvas, exports table-safe HTML.
5. **Control expensive features** (AI, animation, custom HTML) with admin-managed feature flags and usage limits.

## 8. AI Usage & Token Strategy

| Feature | Model | Output | Notes |
|---|---|---|---|
| Template library generation | Sonnet | HTML (one-time) | Test in real Outlook, store curated |
| URL / text autofill | Haiku | JSON ~300-500 tok | Pre-clean page to text, cap 2-3k tokens |
| Design from prompt | Haiku | JSON spec | Layout blocks, palette, font, spacing |
| Screenshot → spec | Sonnet (vision) | JSON | Per-user usage limit |
| Reference analysis (Dribbble etc.) | Sonnet + Batch API | JSON style recipes | One-time, ~50% cheaper |
| Full custom HTML ("wow" mode) | Sonnet | HTML + sanitizer | Admin-enabled only |

**Cost controls**
1. JSON output only, tight `max_tokens`
2. Prompt caching for system prompt, schema, template list
3. Cache results by input hash
4. Per-user daily AI generation limit (set by admin)
5. Structured outputs / tool use to avoid retries
6. Simple edits (color, font, layout) are UI controls, not prompts

## 9. Design Reference Pipeline (Dribbble / Pinterest / Behance)

> Inspiration only. No scraping (ToS + copyright). Do not copy designs.

1. Manually curate 50-100 references in a private Figma/Pinterest board
2. Run each through Claude vision → abstract **style recipe** JSON:
   ```json
   { "layout": "avatar-left", "divider": "vertical-thin", "palette": ["#..."],
     "font_pairing": "serif-name + sans-details", "spacing": "airy",
     "social_style": "outlined-circle", "mood": "editorial" }
   ```
3. Convert recipes into original presets built from Outlook-safe blocks
4. Kimp designers draw the final templates
5. At runtime, send only a short recipe summary in the cached prompt (no images)

| Feature | Member | Designer | Admin |
|---|---|---|---|

| Analytics | – | – | ✓ |
| Team deploy / brand lock | – | – | ✓ |

Enforce on **both UI and API**. Admin turns features on per user or per customer (e.g. animated signature for one specific client).

## 12. Email Client Rules (must follow in the exporter)

- Table-based layout, `cellpadding/cellspacing`, inline CSS only
- Web-safe fonts with fallbacks (Arial, Georgia, Verdana, etc.)
- PNG / JPG / GIF only, hosted on public HTTPS URLs, explicit width/height, alt text
- No base64 images, SVG, flexbox, grid, background images, JS, video
- Transparent PNG logos + dark-mode check
- Animated GIF < 200-300 KB, first frame must be complete (Outlook desktop shows frame 1)
- Test matrix: Gmail web, Outlook web, Outlook desktop (Windows), Apple Mail, iOS Mail, Gmail mobile

### Install methods

| Platform | Method |
|---|---|
| Gmail | Copy-paste or Gmail API push |
| Outlook web / 365 | Copy-paste or admin server-side append |
| Outlook desktop | Copy-paste or `.htm` into Signatures folder |
| Apple Mail | Copy-paste + guide |
| Thunderbird | Paste HTML file |
| Mobile | Copy-paste + guide |

## 14. UI/UX Standards

- Style: SaaS → Glassmorphism / Minimalism
- SVG icons only (no emojis as icons)
- Touch targets ≥ 44×44px, contrast ≥ 4.5:1
- Mobile-first, breakpoints 375 / 768 / 1024 / 1440
- Animation 150-300ms ease-out in / ease-in out, respect `prefers-reduced-motion`
- Semantic color tokens, visible input labels, errors below fields
- Bottom nav max 5 items
- `font-display: swap`, lazy-load images, WebP/AVIF

## 17. Risks

| Risk | Mitigation |
|---|---|
| Outlook rendering bugs | Real-client test matrix + linter, tables only |
| AI cost overrun | JSON-only output, caching, limits, cheap model |
| Image hosting abuse | Size limits, file type checks, per-user quotas |
| Copyright issues | Original templates only, no scraped designs |
| Gmail/Graph API approval delays | Start with copy-paste, add OAuth in Phase 2 |
